# Work finish and resume

Use this for a course/project already connected to the selected vault. These are agent procedures, not background hooks.

## Finish: propose first

Present three independent candidate groups:

- **Outputs:** selected deliverables and a reusable result note; retain the original location and byte/hash version when copying.
- **Key decisions:** adopted choices, reasons and source links. Separate a proposal, hypothesis, implemented behavior and a human-adopted decision. Link a superseded decision to the current replacement rather than erasing its history.
- **Next work:** open questions and the next concrete action, with the owning Linear task. A saved next step is not proof that work started or finished.

For each candidate state destination, evidence, intended reuse and any freshness/coverage gap. Candidate generation writes nothing. Save only candidates selected by the user or an explicit scoped save request. Do not infer full-transcript, cloud-sync, schedule, team publication or Notion approval.

## Save: keep a small handoff

Search the relevant hub and existing session/result notes for the same task and result. Use `templates/session.md` when available; otherwise use the existing answer/result convention. Retain task/hub ID, work/result, decisions and their state, open items, source links/revisions, and next action. Use the existing file helper for selected outputs; note writes go through the correctly targeted Obsidian CLI.

Read before editing shared hub/index/log files and preserve a recoverable previous copy. Link the saved note from the hub/index and log the actual change once. Read back the note and links. Identical content should not add another handoff, copied output or log entry. A copy-only success is not completion of the knowledge update.

## Resume: current work first

1. Read the current hub and latest applicable session/result. Fetch current Linear state when available.
2. Read two or three relevant knowledge notes and the source behind consequential claims. Check source freshness. A stored source is a point-in-time capture; an unavailable remote does not become current because a note says `reviewed`.
3. Recover the adopted decision, open items and next action. Follow explicit supersession/current-source links; a first keyword hit or append-only history is not the current decision resolver.
4. Answer the current task. Separately propose a few relevant notes from other hubs with original scope, why the method transfers, and differences. Do not turn another project's hypothesis into this project's verified fact. Do not collect or edit that other project automatically.

An explicit current-work-only request narrows retrieval. Resume alone is read-only. Report unavailable Linear/source access and distinguish metadata/link checks from factual review. User reproduction and user-confirmed Done remain separate from an agent trial.
