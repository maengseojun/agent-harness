# Visual references: use and observed coverage

Read this when a representation is unfamiliar, the first draft looks like generic boxes, or the user asks for richer expression. Select the relevant source family, inspect an actual example, extract its information job/mark/reading relationship and adapt it to native draw.io. Do not browse every catalogue for a familiar task, copy branded styling or treat gallery claims as domain evidence.

## Where to look

| Source | Useful question | Native adaptation |
|---|---|---|
| [Blocks & Arrows](https://blocksandarrows.com/diagrams/all) | How can containment, responsibilities, fields and different relation lines coexist? | Named boundaries, distinct record/actor roles, labeled connections; use its structure only for real relational information |
| [Data Viz Project](https://datavizproject.com/) | Which alternatives fit the input data and reading purpose? | Consider input and function before shape: dots, intervals, spatial drawings, matrices, sets and combinations, not just flow |
| [Datawrapper tables](https://www.datawrapper.de/tables) | How can exact lookup and visible patterns coexist? | Aligned values with compact in-cell marks, selective emphasis, row grouping and nearby definitions |
| [Datawrapper charts](https://www.datawrapper.de/charts) | How should quantitative patterns be labeled and qualified? | Direct labels, relevant annotations, clear axes/units and declared interval semantics |
| [Our World in Data](https://ourworldindata.org/) | How can a figure support a readable claim? | Pair the claim with the figure, measurement definition, scope/period, interpretation and source |

References expand choices; they do not replace draw.io with another service. Datawrapper's web behavior does not automatically transfer to a static drawing. A catalogue tag is a clue, not a mathematical/semantic classification. If a needed chart is unfamiliar, consult its own explanatory page and relevant field standard before building it.

## Actual examples inspected on 2026-10-13

- [B&A API gateway/auth](https://blocksandarrows.com/diagrams/band/api-gateway-auth-microservices-architecture-diagram-ywr7): visible named Backend enclosure and separately labeled user-data/authorization/query paths. The live page had missing icon images and some bottom UI obstruction; those missing pixels are not verified motifs. Its all catalogue was read, not all 447 pages. Earlier six-board observations remain in [B&A design guide](blocks-and-arrows-design.md).
- [DVP Dumbbell Plot](https://datavizproject.com/data-type/dumbbell-plot/): pairs comparable values on an axis with a connector; useful to expose a difference without a process flow. [Exploded View Drawing](https://datavizproject.com/data-type/exploded-view-drawing/): separated parts and local leaders expose composition. The Function menu was inspected (comparison, concepts, correlation, distribution, geography, whole shares, time trend); no full catalogue/third-party example audit.
- [Datawrapper mini-chart tables](https://www.datawrapper.de/tables#mini-charts): the election example places an exact percentage, bar and historical sparkline on a row with period and source. Data table and mini-chart tabs were read and the latter visually inspected; heatmap functionality was described by the page, not separately rendered in this review.
- [Datawrapper line-chart example](https://www.datawrapper.de/charts): the climate illustration places notes at selected values and directly labels scenarios; its range note specifies simulation percentiles. Inspecting the layout did not revalidate its climate model or every chart type.
- [OWID median-age insight](https://ourworldindata.org/data-insights/europe-is-older-but-latin-america-is-aging-faster): claim above a paired-value figure; age definition, dates, regional scope and interpretation explain what readers should compare. This was design inspection, not a new demographic analysis or complete OWID review.

## Supplied/project visual references

The Boole inequality attachment visible in the task conversation combines a claim, definition/formula, qualitative set view, proof and applications. Use its panel roles when useful, check wording and mathematical meaning, and do not inherit a fixed grid or area-as-probability assumption. A local reread of that original attachment was unavailable in this review, so it is conversation-supplied visual material rather than a newly fetched image.

Accessible existing project output views (workflow check-page-4, policy/prerequisite mapping check-page-5, label/geometry verification) and the 36-page native catalogue supply examples of branches, responsibility/scope alignment and local typography. They are historical task artifacts, not fresh product/source specifications. Only the inspected subset is evidence; other past/cloud project attachments were not exhaustively fetched. Retain their useful alignment and semantic roles without making a flow the default for every document.

## A reference is useful only if it changes a decision

Record a compact choice when relevant: source/example URL, what was observed, the information relationship it solves, the native implementation and anything not verified. Adapt the relation rather than a crowded screenshot. If sources disagree, use the user's question, data and correctness needs to decide. Re-reading source truth and visually checking the delivered native result remain separate jobs.
