# Endix workflow source routing

This personal skill is a reading guide, not a copy of team rules or a team
entry stamp. Fetch current sources for the requested work; do not rely on a
previous summary or a local snapshot as authority.

## Apply at migration, not during personal preparation

Personal brainstorming, research and drafts follow the personal workflow until
the user requests migration into Endix work. An Endix topic alone does not
activate this skill or make a personal draft a team record.

At migration, check the prepared material against the live Endix sources below
before the first team write or implementation. Identify missing criteria and
decisions, carry the authorized material into the applicable team path, and link
its personal source without treating it as team-approved. After migration,
follow the Endix project entry for subsequent work.

## Start with the live entry

Read [How we work](https://www.notion.so/3f28f1ec11b48136b7dec061ebba2df2)
and the target repository's AGENTS.md and entry configuration. For code planning,
implementation or review, also read
[How we build code](https://www.notion.so/3f48f1ec11b481888c2dc4cc51c22ad6).
Follow their live links to the applicable path, domain Rules and templates.
These overview pages are navigation; use the referenced Rules for exact criteria.

Resolve the requested output owner before choosing destinations. Private
preparation retains personal working records and must not be presented as a
stamped team task. For team execution, locate the existing work issue and thread
and read the live entry requirements before any write. Apply the user's actual
authorization within that procedure; this skill grants no additional authority.

Useful entry locators (verify their title and current applicability on fetch):

- [Entry and the lightmap (F0)](https://www.notion.so/3f28f1ec11b48191af1ef6be90623598)
- [Code and doc (F2)](https://www.notion.so/3f28f1ec11b48134b2effda38de1fd5b)
- [Testing and quality](https://www.notion.so/3f48f1ec11b4811eacefdd04384a868a)

## Read only the branch needed for the task

For non-code work, read the applicable path, task row and template from
How we work, including the current destination, approval and communication rules.

For code work, follow How we build code to the applicable Security, architecture,
part, Testing and quality, Conventions and Dictionary pages. Read the task's
separate Spec and Plan and prerequisite results from Linear. Resolve the live
precedence, readiness, ownership, middleman decisions and gate/build boundaries
before editing. Read the applicable BLOCKED and rule-change procedures when
sources conflict, omit a required decision or the work outgrows its plan.

Before a code PR or push, inspect the actual repository gates and applicable
GitHub rules as well as the live PR/reviewer requirements. A documented check,
local hook or installed skill is not evidence that a merge gate is active.
Mechanically enforceable rules belong in the project's gates through its
authorized gate task; do not invent them in this personal skill.

Keep source URLs/IDs, observed revisions, applied sections and any access gap
in the owning working record. Preserve human decisions as human decisions under
the live rules. If a required source is unavailable, stop only the dependent
action, explain the gap and continue independent authorized work.
