# 오류 수정 매뉴얼 1 — 저장과 검증 사이의 오류

같은 오류가 여러 차례 수정 후에도 남거나, 외부 서비스에는 결과가 있는데 자동 검증이 실패할 때 사용한다. 일반적인 모든 코드 오류의 매뉴얼로 확대하지 않는다. Linear 사례를 다룰 때는 [해결 과정과 탐색 기록](references/linear-link-readback.md)을 읽는다.

## 먼저 오류가 발생한 단계를 찾는다

사용자의 마지막 실패 문구, 의도한 입력, 실제 서비스 응답, 별도 재조회 응답을 구분해 확보한다. 과거 설명이나 요약만으로 원인을 확정하지 않는다. 실패를 다음 중 어디서 관측했는지 기록한다.

- 요청·인증·목적지 확인
- 실제 생성·수정
- 별도 조회와 내용 대조
- 영수증·작업 상태 기록
- 수정 버전의 설치·신뢰 승인·실행

동일한 서비스·워크스페이스·대상 ID를 재조회한다. ID, 상태, 본문, 관련 링크 등 수정에 필요한 필드를 확인한다. 표시명이 다른 같은 링크, 여러 번 나타난 URL, 실제로 생성된 여러 객체를 구별한다. 저장 결과가 불확실하거나 이미 존재하면 조회로 조정하고, 검증 오류를 없애려고 생성·전송을 반복하지 않는다. 다른 목적지에 대신 쓰지 않는다.

## 원본으로 작은 재현을 만든다

원본 응답을 비공개 작업 증거로 보존하고, 공유할 재현은 식별자와 내용을 익명화한다. 링크의 표시 글자와 실제 목적지를 각각 비교한다. 본문 내용이 달라졌다면 단순 표현 차이로 분류하지 않는다.

재현에는 다음 세 종류를 포함한다.

| 구분 | 확인할 행동 |
| --- | --- |
| 확인된 표현 변환 | 서비스가 실제로 만드는 같은 URL의 표기 차이는 허용한다. |
| 의미·목적지 변경 | 다른 주소·워크스페이스·대상 ID, 누락·변경된 문장, 체크 상태·코드 변경은 거부한다. |
| 미지원·미확인 표현 | 같다고 추측하지 않고 엄격한 비교나 확인 필요로 남긴다. |

## 공통 검증 지점을 고친다

저장 도구에서 실제 비교 함수와 실패 영수증까지 호출 경로를 따라가고, 바꿀 함수의 호출처를 모두 확인한다. 여러 호출처에 예외를 붙이기 전에 공통 비교 함수에서 해결할 수 있는지 판단한다.

정규화는 관측된 변환에 한정한다. 일반 URL과 `[같은 URL](<같은 URL>)`은 목적지가 같다는 근거가 있을 때 비교할 수 있다. 서로 다른 URL을 표시명만 보고 같다고 하지 않는다. 질의·프래그먼트·ID를 무조건 제거하거나, 본문을 전부 소문자로 바꾸거나, 유사도 점수만으로 성공 처리하지 않는다.

코드·수식·체크 상태처럼 표기가 곧 내용인 부분을 보호한다. 지원하지 않는 복잡한 Markdown은 원문 대조를 유지하는 작은 수정이 전체 파서 제작보다 적절할 수 있다. 허용하는 변환과 엄격하게 남기는 경계를 검사와 설명에 함께 남긴다.

## 수정됐다는 사실과 실제 적용을 따로 증명한다

변경을 덮는 가장 좁은 프로젝트 검사와 의미 있는 실패 검사를 실행한다. 오래 남은 검증 결함이나 외부 쓰기를 잘못 성공 처리할 수 있는 변경은, 가능하면 다른 검토자에게 원본 재현과 거부 사례를 확인하게 한다. 수정·재시도 제한이 있다면 실제 횟수와 실패 근거를 보존한다. 권한·환경 실패를 코드 실패로 세거나, 같은 통과 검사를 이유 없이 반복하지 않는다.

| 확인 대상 | 필요한 증거 |
| --- | --- |
| 소스 수정 | 원본 실패를 재현하고 수정 후 통과한 검사 |
| 설치 | 검토한 파일과 설치 파일의 실제 비교 |
| 실행 허용 | 앱이 보고한 현재 훅·연동 신뢰 상태 |
| 실제 실행 | 의도한 작업의 별도 서비스 재조회와 검증 영수증 |

설치 성공, 합성 호출, `trusted`, 새 대화 시작만으로 실제 실행 성공을 선언하지 않는다. 오래된 버전이 계속 실행되면 현재 실행 경로와 설치 경로를 확인한다. 바뀐 훅의 승인이 필요하면 앱의 정상 승인 절차를 사용하고, 신뢰 해시 조작이나 훅 비활성화로 통과시키지 않는다.

가능하면 이미 저장된 작업의 새 재조회로 검증한다. 새 쓰기가 필요하면 사용자가 허용한 목적지와 범위에서 한 번 수행하고 별도로 조회한다. 원본 응답을 고쳐 만든 파일을 실제 재조회로 제출하거나 실패 영수증을 근거 없이 성공으로 바꾸지 않는다.

## 끝낼 때 남길 것

확인된 원인, 수정 지점, 허용·거부 경계, 실행한 검사, 실제 적용 증거와 남은 범위를 짧게 기록한다. 이번 오류가 해결됐다는 사실을 모든 작업·클라우드 경로가 검증됐다는 주장으로 넓히지 않는다. 사용 중인 작업 기록 정책에 따라 결과를 남기며, 매뉴얼 자체가 외부 쓰기나 Notion 저장 권한을 부여하지는 않는다.
