# Analysis charts (personal addition, MAE-299)

Nine charts for data questions: retention, segments, monitoring, experiments, forecasts, time to an event, attribution and model performance. They were added for easy-understanding from a reference image the user shared (sample data, @isaac.perform). They are drawn in this skill's tokens and local fonts.

Example: [example-analysis.html](../assets/example-analysis.html), generated by `scripts/build_analysis_example.py`. Run it with `--check` to assert every labelled statistic against the plotted data.

Rules for all nine:
- **Colour.**
  - `accent` marks the one focal element: a cell, a panel, a test, a group or a curve.
  - `ink` and `soft` carry everything else.
  - Reference lines are dashed `muted`.
  - Bands are `accent` at low fill opacity.
  - Hex values come only from the style guide.
- **Card.** Each chart gets:
  - a title;
  - a metric line with the unit, the definition and the data cut;
  - the chart;
  - a one-to-two sentence **how to read it** caption;
  - a footer naming when to use it.
- An **advanced** chart always keeps its caption. A smart newcomer cannot read it unaided.
- **Sample data** is said to be sample data.
- **Accessible SVG.** Every `<svg>` has `role="img"`, a `<title>` and a `<desc>`. Put geometry in `x`/`y` attributes, not in `transform`.

## Cohort retention

**Best for:** whether newer cohorts keep customers better at the same age. **Not for:** tiny cohorts, where one leaver looks like a collapse; show counts instead. For a single retention story, use one line per cohort (type-line).

### Layout conventions
- Rows are cohorts, keyed by their start event (first purchase, signup). Each row label carries the cohort size *n*.
- Columns are periods since the start: +0, +1, …
- The +0 column is **cohort entry**, 100% by definition, not a return rate. Label it as entry and draw it neutral (`paper-2`).
- It is a triangle. Cells a cohort has not reached yet stay **empty**, never 0.
- Print the value in every cell.

### Colour
One `ink` opacity ramp on non-focal cells, with heatmap rules (type-heatmap.md). One focal cell in `accent`, excluded from the ramp. Keep cell text at 4.5:1 or more in **both** themes, measured against the composited cell colour. A light ramp (about 0.06–0.30) lets `ink` text work everywhere; flipping to `paper` text mid-ramp fails around 0.4–0.5.

### Honest-data rule
- Define the cell: "returned **in** that period" or "returned **by** that period". They differ.
- The denominator is the cohort size at +0.
- State the data cut. Flag a partial latest period, or end the table at a complete one.
- Compare down a column (same age), not along a row.

### How to read it
"Each row is one cohort; compare a column top to bottom. A blank cell means that age has not arrived yet, not 0%."

### Anti-patterns
- Blank cells drawn as 0.
- A hue per cohort.
- A free colour scale per row.
- A partial current month presented as a drop.

**Reader level:** intermediate. The reader must hold the denominator and the cohort age at once.

## Small multiples

**Best for:** comparing the shape of many series (8–16): which segment behaves differently. **Not for:** four or fewer series (one chart with direct labels), or exact values across segments (a sorted bar or dot plot).

### Layout conventions
- The same mini chart repeats in a regular grid.
- Panel size is identical, and every panel has the **same x and y range**.
- Panel title holds the segment name, plus the last value at the top right.
- Draw a shared reference in every panel, for example ROAS 1×. Name it for what it is: at 1× revenue equals ad spend. Profit break-even is 1 ÷ margin, so state the margin if you draw that line instead.
- State the sort order. Name order is acceptable; an unstated order reads as a ranking.
- No per-panel legends.

### Colour
One focal panel: `accent-tint` fill, `accent` line. All others `paper-2` with `ink` lines.

### Honest-data rule
- Shared scales.
- If a scale must differ, say so in the caption and draw each panel's axis.
- Show volume (spend, *n*) when low-volume panels are noisy.

### How to read it
"Every panel uses the same axis, so heights compare directly; look for the panel whose shape differs."

### Anti-patterns
- Free y scales without a warning.
- The highlighted panel read as "the best". The highlight is editorial.
- An unexplained order read as rank.

**Reader level:** intermediate.

## Control chart

**Best for:** deciding whether a daily metric moved beyond its usual noise. **Not for:** trending, seasonal or autocorrelated series (model the time series), comparing units (funnel plot), or judging against a target. Control limits are not specification limits.

### Layout conventions
- Points in time order, joined by a thin line.
- A solid centre line, and dashed upper and lower control limits with their labels.
- Points outside the limits in `accent`.
- Mark the baseline period and any recalculation point.
- Estimate the centre and limits from a **stable baseline** (Phase I), then apply them unchanged to later points (Phase II). Estimating them over the whole series, signal included, widens the limits with the very points you are testing.

### Colour
Limits and flagged points share `accent`; nothing else does. The centre line is `ink`, and the points are `ink` and `soft`.

### Honest-data rule
- Limits are centre ± 3σ, with σ estimated from **short-term** variation, not the overall standard deviation.
  - Individuals (XmR): σ̂ = mean moving range / 1.128, so the limits are mean ± 2.66 × MR̄.
  - Subgroups: R̄/d₂ or s̄/c₄ (NIST §6.3).
- A rate with a different denominator each day (conversion rate) is shown more honestly as a **p-chart**, with per-day limits p̄ ± 3√(p̄(1−p̄)/nᵢ). Say which chart you drew.
- Choose the run rules before looking: Western Electric or Nelson. More rules mean more false alarms. Recalculate limits only for a known cause or after enough new points.

### How to read it
"The dashed lines are this process's usual range, not a target. A point outside is a signal to investigate, not proof of a cause."

### Anti-patterns
- ±3 overall standard deviations.
- Limits redrawn after every point.
- Limits read as goals.
- A trending series charted as if stable.

**Reader level:** advanced. It needs σ estimation and a rule set.

## Forest plot

**Best for:** comparing many effect estimates with their uncertainty: A/B tests, subgroups, studies. **Not for:** a single result (write the number and its interval), or metrics on different scales.

### Layout conventions
- One row per comparison.
- A marker at the estimate, with a horizontal confidence interval.
- A vertical null line: 0 for differences and lifts, 1 for ratios on a log axis.
- Direction labels under the axis: "← control better / variant better →".
- State the order.
- Square size encodes weight only when results are pooled, and a pooled diamond appears only when pooling is justified.

### Colour
The focal test in `accent`. Rows whose interval excludes the null in `ink`; inconclusive rows in `soft`.

### Honest-data rule
- State the interval level and method (95%, estimate ± 1.96 SE). Use one level for every row.
- Plot ratios on a log scale.
- Many tests make a chance "win" likely: about one in twenty at 95%. Name the multiplicity.

### How to read it
"An interval crossing 0 means 'not yet decided', not 'no effect'. With many tests, one may look significant by chance."

### Anti-patterns
- Mixed interval levels.
- Ratios on a linear axis.
- Box size read as effect size.
- Overlapping intervals taken as proof of no difference.

**Reader level:** advanced. Confidence-interval meaning is the hurdle.

## Fan chart

**Best for:** a forecast with quantified uncertainty that widens with horizon. **Not for:** an unquantified guess (use scenarios), or a single horizon (use an error bar).

### Layout conventions
- Actuals as a solid line, up to a "forecast starts" divider.
- A central path labelled median or mode.
- Nested bands, labelled with their coverage (50, 80, 95%).
- The unit on the axis.

### Colour
Actuals `ink`. The forecast path is a dashed `accent` line. Bands are `accent` at increasing fill opacity toward the centre.

### Honest-data rule
- Bands are **percentile intervals of the predictive distribution**, not minimum and maximum.
- They are conditional on the model's assumptions; say what is held fixed.
- Derive widths from past forecast errors or a bootstrap.
- Skewed quantities such as revenue deserve asymmetric bands. Check calibration against past actuals.

### How to read it
"The bands are probabilities, not limits: the actual value lands outside the 95% band about 5% of the time."

### Anti-patterns
- Bands read as best or worst case.
- Symmetric bands forced on a skewed quantity.
- No divider between actuals and forecast.

**Reader level:** intermediate; advanced when skew is shown.

## Survival curve (Kaplan–Meier)

**Best for:** time to an event, such as churn, when some people have not had it yet at the data cut (censored). **Not for:** data with no censoring (a retention table is enough), tiny groups, or exits with competing causes (cumulative incidence).

### Layout conventions
- A **step** function starting at 100% at t = 0; never smooth it.
- Censor ticks (`|`) sit on the curve.
- A **number-at-risk** row under the x axis.
- A light 95% band (Greenwood) on at least the focal group.
- The median is a dashed drop from 50% to the x axis. If a curve never crosses 50%, write "median not reached".
- Label the curves directly.

### Colour
The focal group is the `accent` line and band. The comparator is the `ink` line.

### Honest-data rule
- Never drop censored people; that biases time downward.
- State the event definition and the data-cut date.
- The tail rests on few people, so stop or fade where few remain at risk.
- Compare like with like. An annual plan can only churn at renewal, so it does not belong on the same monthly curve as a monthly plan.

### How to read it
"Each step down is someone leaving. A tick is someone still subscribed whose outcome we don't know yet. The median sits where the curve crosses 50%."

### Anti-patterns
- Smoothed curves.
- Hidden censoring.
- No at-risk counts.
- A long flat tail read as "safe" when few remain at risk.

**Reader level:** intermediate. Censoring is the one new idea.

## Contribution decomposition

**Best for:** how a model splits each period's outcome into a baseline plus channels, and how that mix shifts (MMM-style). **Not for:**
- measured attribution;
- judging channel efficiency (compare contribution with spend or ROI);
- more than about six series;
- a single period (use type-waterfall).

### Layout conventions
- Weekly x axis; the y axis starts at 0 in outcome units.
- A fixed series order with the **baseline at the bottom**.
- The legend lists the stack top-down.
- Draw the actual outcome over the stack (dots or a line), so the gap to the fit stays visible.
- Negative contributions stack below zero.

### Colour
- The focal channel is `accent`.
- The baseline is neutral (`rule-solid`).
- Other channels are `soft` and `ink`.
- The actual outcome is `ink` with a `paper` halo.

### Honest-data rule
- Say these are **model estimates**, not observations.
- State what the baseline contains.
- Show negative coefficients rather than clip them.
- Say whether segments are posterior means.

### How to read it
"Each slice is the model's allocation, not a measurement; a thick slice is not an efficient channel unless spend agrees."

### Anti-patterns
- A slice read as what the channel caused.
- Series order changed between periods.
- A missing actual line, which hides a poor fit.

**Reader level:** advanced. It needs the idea of a counterfactual baseline.

## Lift chart

**Best for:** choosing how far down a model's ranking to reach when the budget covers only the top N%. **Not for:**
- total capture (cumulative gains);
- comparing datasets with different base rates;
- threshold-free ranking quality (type ROC);
- rare positives (precision–recall).

### Layout conventions
- Rank by score, highest first, so decile 1 is the top 10%.
- Use bars for per-decile lift, or a line for cumulative lift.
- y starts at 0, with a dashed 1× baseline.
- Print the top value, the bin size and the base rate.

### Colour
The top decile in `accent`. Other deciles above 1× in `ink`; deciles below 1× in `rule-solid`.

### Honest-data rule
- Say **per decile** or **cumulative**; they differ everywhere except the top decile.
- With equal-size deciles, per-decile lift averages exactly 1×.
- Use held-out data. Small bins are noisy.

### How to read it
"2.6× means the top 10% respond at 2.6 times the average rate, not 2.6 times the sales."

### Anti-patterns
- Unlabelled cumulative versus per-bin.
- Lift read as volume.
- Lift compared across different base rates.

**Reader level:** intermediate.

## ROC curve

**Best for:** a classifier's ranking quality across all thresholds when prevalence or costs are unknown. **Not for:**
- rare positives where false-positive counts matter (precision–recall curve);
- a fixed capacity (lift or precision@k);
- probability calibration (calibration plot).

### Layout conventions
- A **square** plot, both axes 0–1: false positive rate on x, true positive rate on y.
- A step line from (0,0) to (1,1); a finite sample is a staircase.
- A dashed diagonal labelled "random, 0.5".
- An AUC label that names the data split and size, for example "held-out n=120, positives 60".
- At most three curves, labelled directly.

### Colour
The curve in `accent`, with the area under it at low fill opacity. The diagonal is dashed `muted`.

### Honest-data rule
- AUC is measured on held-out or cross-validated data, never on training data.
- AUC equals the probability that a random positive outranks a random negative. The example cross-checks the trapezoid area against that probability.
- A higher-AUC model can still lose in one false-positive-rate region.

### How to read it
"AUC 0.82 is not 82% accuracy: it is the chance the model scores a random positive above a random negative."

### Anti-patterns
- AUC read as accuracy.
- A smoothed curve.
- An unstated split.
- ROC used for rare positives without a precision–recall view.

**Reader level:** intermediate. TPR, FPR and the threshold are prerequisites.
